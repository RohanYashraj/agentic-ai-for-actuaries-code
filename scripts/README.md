# scripts/ — Build and maintenance tooling

## `build_demos.py` — drift-proof browser demos

The website runs the book's deterministic tool scripts directly in the
visitor's browser (Python compiled to WebAssembly). Those browser
copies are **never written by hand**: this script generates them from
the chapter originals at build time, so they cannot drift from the
code in the book.

What the transform does to each entry script:

- strips `agno` imports and `@tool` decorators (verified against the
  AST, including function-local imports),
- deletes module-level `Agent(...)`/`Workflow(...)` constructions,
- rewrites `x.entrypoint(...)` calls to plain `x(...)`,
- optionally replaces the `__main__` block with a browser-friendly one
  from `overrides/` (declared per demo in `demos.config.json`),
- then **fails loudly** if anything agno-shaped survives, or if the
  result no longer parses/compiles.

Output goes to `web/public/demos/` (gitignored — regenerated by the
website's `predev`/`prebuild` hooks). CI runs `--check` on every PR
via `.github/workflows/demos-check.yml`, so a chapter edit that the
transform cannot handle breaks the build instead of the website.

```bash
python3 scripts/build_demos.py --out web/public/demos   # build
python3 scripts/build_demos.py --check                  # CI verify
```

### Adding a demo

Add an entry to `demos.config.json` (chapter dir, entry file, support
files, data files, Pyodide packages, title/description). If the
original's `__main__` block runs an agent, add a
`overrides/<id>_main.py` with a plain-Python equivalent and reference
it as `main_override`.

## `export_waitlist.py`

Exports the launch waitlist collected by the website
(`POST /api/py/waitlist`, stored in Upstash Redis) as CSV:

```bash
uv run --env-file .env python scripts/export_waitlist.py > waitlist.csv
```
